# 학습량 분석 웹 앱 정량 평가 (2026-10-27)

NCS 인공지능 플랫폼 구축 학습모듈 9권(794개 검색 단위, 63개 세부 단원)을 색인한
로컬 환경(RTX 4080 16GB, Qwen3-8B)에서 측정했다. 측정 스크립트는
[scripts/measure_study_app.py](../scripts/measure_study_app.py)이며 결과 원본은
`artifacts/measurements/study_app.json`(로컬, Git 제외)에 저장된다.

## 평가 문항 구성

- 정답 단원은 모델이 아니라 **NCS 문서 구조**로 정했다. 학습모듈의 절 번호
  (`1-1. 요구사항 수집하기`)와 수행 내용 머리말을 따라 구절을 단원에 배정했다
  ([src/ncs_structure.py](../src/ncs_structure.py), 794개 중 789개 배정, 63개 단원 모두 포함).
- 단원마다 앱이 단원 연결에 쓰는 대표 구절을 **제외한** 구절 2개를 무작위로 골라
  Qwen3-8B가 수험생 질문을 한 문장씩 만들었다. 구절이 부족한 단원이 있어 총 123문항이다.
- 한계: 질문을 교재 구절에서 생성했으므로 실제 수험생 질문보다 교재 표현과 가깝다.
  인접 단원은 원문에서도 내용이 겹치므로(예: 요구사항 정의 절의 우선순위 기준) 단원 정확 일치는 엄격한 지표다.

## 해석

- 근거 검색과 에이전트 기능은 계획서 목표를 넘었다. 다만 퀴즈 "성공"은 형식과 근거
  번호의 유효성이며, 정답 내용의 사실성은 사람이 따로 검토하지 않았다.
- 응답 시간 목표(2초)는 달성하지 못했다. 검색 1회 답변이 2.9초로 가장 가깝고,
  논문 정책은 중간 답변을 단계마다 생성하므로 15.5초가 걸린다.
- 논문 정책은 한국어 NCS 질문에서 75%(92/123)를 최대 4회까지 검색했고, 근거 정확도는
  검색 1회 대비 0.8%p 높았다. 영어 벤치마크에서 보정한 임곗값이라 한국어에서는 검색을
  줄이는 효과가 나타나지 않았다.
- 질문→단원 연결은 처음 단원 이름 임베딩 비교 방식에서 정확한 단원 26.8%였다.
  검색된 근거 구절의 문서 구조 단원으로 투표하도록 바꾼 뒤 87.8%가 되었다(같은 123문항).
